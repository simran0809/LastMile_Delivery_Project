Problem Statement

What's broken in last-mile logistics today?

Last-mile delivery is the most expensive, complex, and failure-prone leg of the supply chain. For small and mid-size logistics operations, these pain points compound daily.

💸

Opaque, Inconsistent Pricing

Charges are calculated manually or differ between staff — customers don't see the breakdown before they commit, leading to disputes and distrust.

📍

Manual Agent Assignment

Dispatchers spend hours matching orders to agents based on gut feel. Nearest available agents are often missed, increasing delivery times and fuel costs.

🔇

Zero Customer Visibility

Customers have no way to track their parcel in real time. They call support repeatedly, overwhelming staff and creating poor experiences.

🗂️

No Delivery History or Audit Trail

When a delivery fails or is disputed, there is no timestamped record of who did what and when — making accountability impossible.

🔄

Failed Delivery Dead Ends

When an attempt fails, there's no structured flow to notify the customer, capture a new date, and reassign the order — it simply gets lost or re-entered manually.

⚙️

Hardcoded Rate Cards

Pricing rules are embedded in code or spreadsheets. Any change to rates, zones, or surcharges requires a developer and a redeployment.

Key Features

Everything built into the platform

From the pricing engine to the notification system, every feature was designed to remove a specific operational pain point.

📐

Volumetric Weight Engine

Calculates L×B×H ÷ 5000, compares with actual weight, and bills on the higher of the two — the industry-standard dimensional weight formula.

🗺️

Zone-Based Rate Cards

Separate B2B and B2C rate cards, each with independent intra-zone (local) and inter-zone (outstation) rates, base weight, and per-kg add-on charges.

📡

GPS Auto-Assignment

Uses the Haversine formula to calculate great-circle distance between the pickup area and every available agent's last known GPS coordinates — assigns the nearest one instantly.

📬

Email + SMS Notifications

Every status change triggers an HTML email via Nodemailer (Ethereal SMTP for testing) and a simulated SMS — both logged in the Notification Simulator panel.

📜

Immutable Tracking Timeline

Each status transition is permanently logged with the actor's name, role, timestamp, and remarks. The history can never be edited or deleted.

🔄

Failed Delivery + Reschedule Flow

Agent selects a structured failure reason, the system frees the agent, notifies the customer, and lets them pick a new delivery date — then the order re-enters the assignment queue.

🔐

Role-Based Auth (JWT)

Every API endpoint is guarded by JWT authentication and role-based authorization — customers can't access admin routes, agents can't see other agents' orders.

🖥️

Admin Rate Card UI

Admins update zone rates, COD surcharges, and base weights from the dashboard without touching a single line of code. Changes apply to all future orders immediately.

🗾

Interactive Map Picker

Customer clicks on the map to set pickup and drop locations — the system snaps the pin to the nearest area, draws a route line, and auto-fills the area selector.

Order Journey

Full lifecycle of a delivery order

From placement to doorstep — every step is tracked, notified, and logged.

1
Customer / Admin

Order Placed

Customer enters pickup & drop addresses, selects areas on map, fills package dimensions and weight. System calculates volumetric weight, looks up the correct rate card (B2B or B2C), applies zone multiplier, adds COD surcharge if applicable, and shows the total before confirmation.

2
Admin

Agent Assigned

Admin either selects an agent manually from a dropdown or clicks "Auto" to trigger GPS-based auto-assignment. The Haversine engine calculates distance from the pickup area to every available agent and assigns the closest one. Agent status flips to "busy".

3
Delivery Agent

Picked Up → In Transit → Out for Delivery

Agent steps through the status sequence from their dashboard. Each transition is logged with timestamp and actor name. Customer receives an email and SMS notification at every step.

4A
Successful Path

Delivered ✓

Agent marks the order as Delivered. The tracking timeline is sealed. Customer receives final delivery confirmation email. Agent status returns to "available" for new assignments.

4B
Failure Path

Failed → Rescheduled

Agent selects a failure reason (refused, wrong address, not home, cash not ready, damaged package). Agent is freed immediately. Customer receives a failure notification and sees a reschedule form. Customer picks a new date — order resets to "Placed" unassigned and re-enters the queue.
